# GCP Migration Wizard

GCP 프로젝트를 다른 계정/프로젝트로 이관할 때 필요한 **6단계(Phase 0~6) 명령어를 자동 생성**하고, 진행 상황을 체크리스트로 추적하는 웹 GUI 도구입니다. 주언어는 **Go**이며, 외부 의존성 없이 표준 라이브러리만 사용합니다.

이 도구의 Phase 구성과 "발견된 이슈"는 실제 이관 히스토리(아래 참고)를 그대로 반영했습니다.

## 설계 근거 (예전 이관 히스토리)

이 저장소는 이미 두 차례 프로젝트 이관을 수행했고, 그 과정과 함정이 문서/커밋에 기록되어 있습니다.

| 이관 | 방향 | 관련 PR |
|------|------|---------|
| 1차 | 구 프로젝트 → `yango-495502` | #1087, #1089 |
| 2차 | `yango-495502` → `yango-501407` | #1096, #1097, #1098, #1099, #1101 |

- 기준 문서: `claudedocs/migration-to-new-gcp.md` (Phase 0~6 체크리스트 + 실행 중 발견 이슈)
- 기본값(`DefaultConfig`)은 2차 이관 결과인 `yango-501407`을 "구 프로젝트"로 놓고 채워져 있어, 다음 이관 시 **신 프로젝트 정보만** 입력하면 됩니다.

도구에 내장된 주요 "함정" 경고도 히스토리에서 추출했습니다.

| 경고 반영 위치 | 원인(히스토리) |
|----------------|----------------|

| Phase 3 · `POSTGRES_HOST` 갱신 확인 | #1098 — `null_resource`가 `POSTGRES_SERVER`만 갱신하던 버그 |
| Phase 3 · 미관리 `hotsao` DB 사전 생성 | #1099 — Terraform 미관리 수동 DB 존재 |
| Phase 5 · Cloudflare A레코드 전환 | #1100 — 실제 권위 DNS는 Cloudflare, Cloud DNS는 `_acme-challenge`용 |
| Phase 5 · cert-manager DNS-01 SA 교체 | 구 프로젝트 SA 키 사용 시 삭제 후 인증서 갱신 깨짐 |

## 사용 방법

- 실행: 이 디렉토리에서 `go run .`
- 접속: 브라우저가 자동으로 `http://127.0.0.1:8787` 을 엽니다 (자동 오픈 끄기: `go run . -no-open`)
- 포트 변경: `go run . -addr 127.0.0.1:9000`
- 바이너리 빌드: `go build -o gcp-migrator .` 후 `./gcp-migrator`

사용 흐름:

1. **설정** 화면에서 신 프로젝트 ID 등 이관 정보 입력 → "저장하고 명령 생성"
2. 좌측 네비게이션에서 Phase 0 → 6 순서로 진행
3. 각 단계의 명령 카드에서 "복사" 버튼으로 명령을 가져와 **사용자가 직접 실행**
4. 완료한 단계는 체크박스로 체크 → 진행률이 자동 저장됨

## 실행 방식

각 명령 카드에는 **복사**와 **▶ 실행** 두 버튼이 있습니다.

| 버튼 | 동작 |
|------|------|
| 복사 | 명령을 클립보드로 복사 (사용자가 터미널에서 직접 실행) |
| ▶ 실행 | `/api/run`이 로컬 셸(`bash -lc`)로 실행하고 결과를 웹 UI에 실시간 스트리밍 |

- "▶ 실행"은 로컬 gcloud/kubectl **인증을 그대로** 사용합니다 (서버가 127.0.0.1 에만 바인딩, 실행 주체는 로컬 사용자 본인).
- 결제 계정 등 읽기전용 조회는 "불러오기" 버튼(`/api/lookup/billing`)으로 gcloud 인증을 활용해 자동 입력합니다.

## 안전 설계

- 되돌리기 어려운 명령(apply, `gcloud projects delete` 등)은 🚨 **빨간색 danger 카드**이며, "▶ 실행" 시 **확인 창**이 뜹니다.
- 서버는 **127.0.0.1 전용 바인딩**이라 외부에서 접근 불가합니다.
- `gcloud projects delete` 같은 대화형 확인 명령은 비대화형(TTY 없음) 실행 시 `--quiet` 없이는 중단됩니다 (의도된 안전장치).
- 입력값/진행상태는 로컬 파일(`.migrator-config.json`, `.migrator-state.json`)에만 저장되며 `.gitignore`로 커밋에서 제외됩니다. 시크릿 목록에 민감정보가 들어갈 수 있으므로 주의하세요.

## 버전 정보

| 항목 | 값 | 비고 |
|------|-----|------|
| go.mod 선언 | `go 1.26` | 로컬 설치 `go1.26.2` 라인에 맞춤 |
| 최신 안정판 | `go1.27.3`, `go1.26.10` (조회일 2026-11-09) | — |
| 의존성 | 없음 (표준 라이브러리만) | `go.sum` 불필요 |

> go.mod를 `1.27`로 올리면 로컬 toolchain(1.26.2)에서 빌드 시 1.27 toolchain 자동 다운로드가 강제됩니다. 불필요한 다운로드를 피하기 위해 설치된 `1.26` 라인으로 유지합니다. 로컬 toolchain을 `go1.27.x`로 올린 뒤에는 go.mod의 go 지시문도 함께 올리는 것을 권장합니다.

## 구조

| 파일 | 역할 |
|------|------|
| `main.go` | HTTP 서버, 정적 파일 embed, 설정/상태 저장 API, 라우팅 |
| `migration.go` | 설정 모델 + Phase 0~6 명령어 생성기 (히스토리 반영) |
| `lookup.go` | 읽기전용 gcloud 조회 (`불러오기` 버튼: 결제 계정 등) |
| `run.go` | 명령 실행 + 실시간 스트리밍 (`▶ 실행` 버튼) |
| `web/index.html` · `style.css` · `app.js` | 세련된 다크 테마 위저드 UI (프레임워크 없음) |
