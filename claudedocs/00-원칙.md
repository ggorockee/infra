# 이 프로젝트의 최우선 원칙

작성일: 2026-11-27. 모든 작업(인프라, 앱, 광고, 운영)에 다른 규칙보다 먼저 적용합니다.

## 1. 모든 것은 문서로 남긴다

대화나 기억에만 있는 정보는 다음 작업에서 사라집니다. 결정, 절차, 겪은 문제, 남은 일은 작업이 끝나기 전에 문서에 적습니다.

| 언제 | 무엇을 | 어디에 |
|---|---|---|
| 작업을 시작할 때 | 진행 중인 계획 문서의 "다음 세션 시작 가이드"부터 읽음 | `claudedocs/planning/` (로컬 전용 계획 문서) |
| 결정이 나올 때 | 누가 무엇을 언제 정했는지 | 계획 문서 해당 항목 아래 한 줄 |
| 운영 사실이 바뀔 때 | 배포 경로, 알림, 계정·연동 상태 | `.claude/CLAUDE.md` 운영 현황 |
| 절차를 처음 해 볼 때 | 단계, 필요한 권한·시크릿, 막힌 곳과 해결 | 절차서 (예: `claudedocs/app-release-runbook.md`) |
| 문제를 해결했을 때 | 증상 → 원인 → 해결 | 절차서의 "겪은 문제와 해결" 표 |
| 비밀번호·키를 만들거나 옮길 때 | 값이 아니라 위치 | `.secrets/README.md` (로컬 전용) |
| 작업을 마칠 때 | 한 일(PR 번호), 남은 일, 다음 확인 날짜 | 계획 문서 진행 기록·시작 가이드 |

- 작업을 마쳤다고 말하기 전에 위 문서가 갱신됐는지 확인합니다. 문서 갱신이 빠진 작업은 끝난 작업이 아닙니다.
- 저장소가 공개이므로 커밋하는 문서에는 금액, 수입, 사용자 수, 광고 고객 ID, 비밀 값을 적지 않습니다. 이런 값은 로컬 전용 문서(`claudedocs/planning/`, `.secrets/`)에 적습니다.
- `*.md`에는 JSON·표 외의 코드 블록을 넣지 않고, 명령은 인라인 코드로 적습니다.

## 2. 모니터링할 수 없는 것은 관리할 수 없다

새로 만들거나 바꾼 것은 "잘 되고 있는지"를 볼 수 있어야 끝난 것입니다.

| 만들거나 바꾼 것 | 함께 해야 할 것 |
|---|---|
| 서비스·배포 | 지표 수집(ServiceMonitor 등), 대시보드 패널, 알림 규칙 |
| 앱 기능 | 사용 이벤트(자체 서버 허용 목록 또는 GA4), 대시보드에서 볼 수 있게 |
| 앱 출시 | 스토어 공개·버전, 비정상 종료, 광고 승인 상태가 수집기에 보이게 |
| 광고·외부 계정 설정 | 효과를 볼 지표(노출·설치·잔존·수입)와 점검 날짜를 계획 문서에 |
| 알림 | 대시보드 색상 기준과 같은 기준값, 정상·경고·조치 범위표와 차트 설명 |

- 지표가 없는 상태로 배포했다면 "모니터링 없음"을 계획 문서에 할 일로 남깁니다.
- 알 수 없는 상태(데이터 없음)를 "정상"으로 보고하지 않습니다. 확인한 숫자와 출처를 함께 적습니다.
- 머지로 끝내지 않고 ArgoCD 상태, Pod, 실제 지표·메일·로그까지 확인합니다.

## 3. 상태 확인 방법

| 대상 | 방법 |
|---|---|
| 세 앱 출시·광고·알림·수입·잔존율 | `python3 scripts/app-status.py` (읽기 전용) |
| 클러스터·서비스 | Grafana https://monitoring.ggorockee.com (`cluster-overview`, `app-ads-overview` 등) |
| 배포 | ArgoCD Synced/Healthy, `kubectl get pods -A` |
| 경고 메일 | Alertmanager → 수신 메일 (등급별 반복 주기는 CLAUDE.md) |
