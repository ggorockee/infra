# 업데이트 안내 카드 (세 앱 공통 표준)

2026-11-27 개발자 결정: **앞으로 앱 업데이트는 이 카드로 알린다.** 리뷰맵은 2.2.3부터, 돌려받엔·라익찍스는 다음에 내는 버전부터 적용한다. 기준 구현은 리뷰맵이다.

## 언제 보이나

| 상황 | 카드 | 버튼 | 닫으면 |
|---|---|---|---|
| 업데이트한 뒤 첫 실행 | 새로워진 점 | 다음 → 확인했어요, 닫기(X) | 그 버전에서는 다시 안 뜸 |
| 새 버전이 있음 (현재 < latest) | 새 버전 안내 | 업데이트 하기, 나중에, 닫기(X) | 정한 기간 동안 건너뜀 (리뷰맵 3일, 돌려받엔·라익찍스는 지금 규칙대로 버전당 1회) |
| 강제 업데이트 (현재 < min) | 업데이트 필요 | 업데이트 하기만 | 닫을 수 없음. 스토어에 다녀와도 남음 |
| 새로 설치 | 없음 | - | - |

| 규칙 | 이유 |
|---|---|
| 한 번에 카드 하나만. 새 버전 안내가 있으면 새로워진 점은 다음 실행으로 | 카드가 연달아 뜨면 읽지 않음 |
| 카드를 닫기 전에 앱을 끄면 다음 실행에 다시 | 못 본 것으로 처리 |
| 버전 확인에 실패해도 앱에 든 새로워진 점은 보여줌 | 오프라인 대비 |
| 바깥을 눌러서는 닫히지 않음. Android 뒤로 가기는 닫기와 같음(강제 제외) | 실수로 닫는 것 방지 |

**업데이트 전 카드는 이미 설치된 옛 버전 앱이 띄운다.** 따라서 이 기능이 든 버전을 설치한 사람에게 그다음 버전부터 보인다. 그 전 버전 사용자는 예전의 작은 팝업을 본다.

## 화면

| 항목 | 값 |
|---|---|
| 크기 | 화면 가로 90%, 세로 80% |
| 구성 | 위: 라벨(새로워진 점 · v2.2.3 / 새 버전 v2.3.0)과 닫기. 가운데: 넘겨 보는 장. 아래: 점과 버튼 |
| 장 수 | 1~3장. 1장이면 점과 "다음" 없이 바로 확인 버튼 |
| 한 장 | 그림(없으면 아이콘), 제목, 설명. 넘치면 장 안에서 세로 스크롤 |
| 태블릿 | 글자·버튼 1.5배, 그림 영역 확대, 버튼 폭 560까지 |
| 확인한 조건 | 320x568, 375x812, 768x1024, 가로 812x375에서 글자 배율 1.0·1.3·1.6 넘침 없음 (위젯 테스트) |

## 내용 형식

앱에 든 `release_notes.json`(업데이트 후. 리뷰맵 `asset/`, 돌려받엔·라익찍스 `assets/`)과 Remote Config `release_note`(업데이트 전·후)가 같은 형식을 쓴다.

```json
{
  "version": "2.3.0",
  "pages": [
    {
      "title": "첫 장 제목",
      "body": "한두 문장 설명",
      "image": "asset/image/release_notes/example.png",
      "icon": "calendar"
    }
  ]
}
```

| 항목 | 규칙 |
|---|---|
| version | 설치된 버전(업데이트 후) 또는 Remote Config의 latest(업데이트 전)와 같아야 사용 |
| pages | 3장까지. 제목 없는 장은 무시. 알릴 것이 없는 버전은 빈 배열 |
| title / body | 제목은 20자 안팎, 설명은 두 문장까지. 사용자가 얻는 것을 씀 (코드·내부 용어 금지) |
| image | 앱에 든 그림(리뷰맵 `asset/...`, 폴더 이름이 다른 앱은 이식할 때 그 경로를 허용: 돌려받엔·라익찍스 `assets/...`) 또는 `https://` 주소만. 업데이트 전 카드는 옛 앱에 새 그림이 없으므로 https 주소를 쓰거나 생략 |
| icon | bell, calendar, map, new, star, text, update 중 하나. 그림이 없거나 못 불러올 때 표시 |
| 그림 | 가로 900px 안팎 PNG, 100KB 안팎. 실제 업체명 대신 "예시"를 표시한 데이터. 지난 버전 그림은 지움 |

## 원격 내용 우선순위

| 카드 | 1순위 | 2순위 |
|---|---|---|
| 업데이트 후 | `release_note` (version = 설치된 버전) | 앱에 든 파일 |
| 업데이트 전 | `release_note` (version = latest) | 한 장짜리 기본 안내 (업데이트 문구 키가 있으면 그 문구) |

## 릴리스마다 할 일

| 순서 | 할 일 |
|---|---|
| 1 | 앱 버전 올리기 (리뷰맵은 `pubspec.yaml`과 `app_version.dart` 함께) |
| 2 | `asset/release_notes.json`의 version과 pages 갱신. 필요하면 그림 생성 |
| 3 | 테스트 통과 확인: 파일의 version이 앱 버전과 다르면 실패, 가리키는 그림이 없으면 실패 |
| 4 | 출시 전 확인: 이전 버전을 설치해 실행 → 새 버전을 덮어 설치 → 카드 1회, 닫은 뒤 재실행에는 없음, 새 설치에는 없음 |
| 5 | 스토어 공개 확인 후 Remote Config `release_note`(새 버전 내용)와 `*_latest_version` 갱신. 배포 전에 라이브 값과 저장소 원본을 비교 |
| 6 | 출시 1주 뒤 GA4에서 이벤트 확인 |

배포 전 비교가 필요한 이유: 2026-11-27 리뷰맵 라이브 `ios_latest_version`이 저장소 원본보다 앞서 있었다. 원본 그대로 배포했다면 값이 되돌아갔다.

## 측정

| 이벤트 | 매개변수 |
|---|---|
| `update_card_shown` | card_type(after, optional, force), note_version, page_count |
| `update_card_action` | card_type, note_version, action(confirm, update, later, close), last_page(가장 멀리 본 장) |

| 확인할 것 | 해석 |
|---|---|
| optional의 update 비율 | 안내가 업데이트로 이어지는지 |
| last_page 분포 | 뒷장을 보는지. 대부분 1이면 장 수를 줄이고 중요한 것을 첫 장에 |

GA4 화면에서 매개변수별로 나누어 보려면 관리 → 맞춤 정의에 card_type, action, last_page를 등록해야 한다(계정 설정이라 개발자가 함). 등록 전에도 이벤트 수는 보인다. Grafana 패널은 아직 없다. 첫 점검일은 리뷰맵 2.2.3 공개 1주 뒤다.

## 다른 앱에 적용

| 앱 | 지금 | 적용 | 필요한 일 |
|---|---|---|---|
| 리뷰맵 | 적용 | 2.2.3 | 출시 후 Remote Config 배포·측정 |
| 돌려받엔 | 작은 팝업 (`lib/ui/update_gate.dart`, 문구 `update_message`) | 1.1.1 | 카드·서비스 이식, `release_note` 키 추가. 쓰던 사용자 판단은 온보딩 완료 값(`onboarding.done`). 이벤트를 서버 허용 목록에 추가 |
| 라익찍스 | 작은 팝업 (`lib/widgets/update_dialog.dart`, 문구 `update_message`) | 다음 버전 | 카드·서비스 이식, `release_note` 키 추가. **첫 실행에 저장하는 값이 없어** 신규 설치 구분 방법을 먼저 정해야 함(설치·갱신 시각 비교 또는 이번 버전에 표시를 저장하고 그다음 버전부터 보여주기). 이벤트를 서버 허용 목록에 추가 |
| 새 앱 | - | 첫 출시부터 | 첫 실행 표시를 저장하고 카드를 넣음 |

이식할 때 바꾸는 것: 앱 색(테마를 따름), 버전 비교 방식(각 앱의 `AppVersion`), 이벤트 기록 방식, 건너뛰기 규칙. 화면 규칙과 내용 형식은 바꾸지 않는다.
